# 🔄 5.0 — Credential Rotation Runbook (insightWOS)

**Trigger:** DB password (`ywYBamE6...`) dan metadata project pernah dipaparkan di chat.
**Project:** `verwobaejumvpagwynae` (insightWOS, region ap-northeast-1).
**Estimasi:** 15–20 menit. Downtime nol jika urutan diikuti.

## Prinsip urutan

Rotate → update env **local dulu** → verifikasi lokal → update **Vercel** → verifikasi production.
Jangan update Vercel sebelum env lokal terbukti jalan — kalau ada yang salah, rollback satu tempat saja.

⚠️ **1 aturan emas:** setiap kali password DB di-rotate, **service_role key JUGA di-rotate** (kredensial yang sama terpapar), dan sebaliknya.

---

## Langkah 1 — Rotate password database

Dashboard → **Project Settings → Database → Database password → Reset database password**.
Simpan password baru di password manager, **jangan** tempel di chat/issue.

## Langkah 2 — Update env lokal (`.env.local`)

Update nilai berikut (password baru di URL `DATABASE_URL`, format pooler tetap sama):

```
DATABASE_URL=postgresql://postgres.<ref>:<PASSWORD_BARU>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres
VITE_SUPABASE_URL=https://verwobaejumvpagwynae.supabase.co
# (anon/service_role hanya berubah jika Langkah 6 dijalankan bersamaan)
```

> Catatan: `.env.local` saat ini mengandung blok SQL INSERT mentah yang membuat dotenv gagal parse (ditemukan saat deploy CLI). Sambil di sini, pindahkan blok SQL itu ke file `.sql` terpisah supaya `supabase` CLI & dotenv tidak error.

## Langkah 3 — Verifikasi lokal

```bash
# koneksi DB
psql "$DATABASE_URL" -c "select 1;"
# atau: python -c "import pg8000.native,os; c=pg8000.native.Connection(os.environ['DATABASE_URL'].replace('postgresql','postgres'), ssl_context=ssl.create_default_context()); print(c.run('select 1'))"

# app + edge function
npm run dev      # login worker → tab worker tampil
npm run build    # tidak ada error env
```

## Langkah 4 — Update Vercel

```bash
vercel env rm DATABASE_URL production --yes
vercel env add DATABASE_URL production   # paste password baru
# atau via dashboard: Project → Settings → Environment Variables
```

Jika `SUPABASE_SERVICE_ROLE_KEY` di-rotate (Langkah 6), update juga env yang memakainya.

## Langkah 5 — Verifikasi production

```bash
vercel --prod            # deploy ulang agar env baru ter-bake
curl -s https://<app>.vercel.app/api/health 2>/dev/null || buka app, login worker
```

Cek: login worker sukses, sb-token muncul, tab worker OK (sama seperti acceptance test Tahap 4B).

## Langkah 6 — Rotate service_role key (wajib, sebab terpapar juga)

Dashboard → **Project Settings → API → service_role → Rotate**. Lalu:

1. Update `SUPABASE_SERVICE_ROLE_KEY` di `.env.local` + Vercel (deploy ulang).
2. **Edge functions memakai `SUPABASE_SERVICE_ROLE_KEY` otomatis dari runtime Supabase** (bukan dari repo) — TIDAK perlu redeploy edge functions karena rotasi ini.
3. Scriptor audit/batch yang membaca service role dari env lokal: update env-nya.

## Langkah 7 — Close the loop

- [ ] Password lama tidak ada lagi di env mana pun (grep repo & CI)
- [ ] `vercel logs` bersih, tidak ada 401/403 dari DB
- [ ] Ceklis 5.0 di REKAP di-tick
- [ ] Commit runbook ini (tanpa nilai kredensial!) + hapus referensi `ywYBamE6...` dari dokumen/chat archive yang masih bisa diedit

## Rollback

Jika production rusak setelah rotasi: kembalikan env Vercel ke nilai sebelumnya (password lama **masih valid** selama tidak di-reset dua kali — reset di dashboard selalu menghasilkan password baru, tidak bisa "un-rotate"). Kalau terlanjur dua kali reset, ulangi Langkah 2–5 dengan password terbaru.
